# Лог решений (проектный уровень)

Формат записи: `[дата время] — решение — обоснование — версия package.json`. Время — по местному времени клиента (IST, Ирландия), см. `templates/`.

Этот файл — **публичный**, репозиторий открытый: сюда попадают только решения об архитектуре и процессе проекта. Решения, касающиеся конкретного клиента (его цели, программа, план питания), фиксируются в `clients/<slug-клиента>/decisions-log.md` — эта папка в `.gitignore` и наружу не публикуется.

## 2026-08-29 11:16 IST — версия 0.9.0

- **Решение:** сделаны два независимых входа для администрирования — веб-админка (`src/admin/server.js`, HTTP Basic Auth логином/паролем из `.env`) и роли прямо в боте (таблица `admins`, команды `/stats`/`/clients`/`/admins`/`/addadmin`/`/removeadmin`) — явный запрос, две разные точки входа, а не одна общая.
- **Решение:** права в боте — `owner` (один, назначается через `OWNER_TELEGRAM_ID` в `.env`, закрепляется при старте бота) и `admin` (может назначать других `admin`, но не может удалять). Удалять администраторов может только `owner` — так и запрошено.
- **Решение:** доступ к веб-админке не завязан на роли `admins` из бота — это отдельный общий логин/пароль (`ADMIN_WEB_USER`/`ADMIN_WEB_PASSWORD`), т.к. в вебе нет понятия «текущий telegram-пользователь», через который можно было бы проверить роль.
- **Решение:** редактирование анкеты в веб-админке ограничено CRUD вопросов и управлением их составом/порядком в стратегиях (добавить/убрать/подвинуть ▲▼) — без визуального drag-n-drop и без клиентского JS, чтобы не тащить сборку фронтенда ради внутреннего инструмента на несколько страниц.
- **Обоснование:** явный запрос — веб-админка для редактирования анкеты и просмотра клиентов, плюс роли обычный пользователь/админ/владелец в самом боте с управлением через команды.
- **Статус:** веб-админка проверена через `curl` (авторизация, CRUD вопросов, список клиентов) — не проверена вживую в браузере. `OWNER_TELEGRAM_ID` не заполнен (не было под рукой Telegram ID владельца) — пока никто не назначен владельцем/админом, `/addadmin` и `/removeadmin` некому вызвать, кроме как через прямое редактирование таблицы `admins`.
