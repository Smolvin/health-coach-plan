## [0.8.0] — 2026-08-29 10:49 IST
### Added
- Сценарий онбординга в боте: `/start` спрашивает имя, город, дату рождения, нужна ли программа — и по одному проводит через анкету, сохраняя каждый ответ сразу в MySQL (`clients`, `questionnaire_answers`).
- Анкета вынесена из кода в БД: таблицы `survey_strategies` / `survey_questions` / `survey_strategy_questions` (`migrations/`, `npm run migrate`) — состав, порядок и текст вопросов теперь редактируются в базе, без деплоя.
- Две стратегии анкеты — короткая (9 вопросов) и полная (17), выбор — кнопкой после вопроса «нужна ли программа».
- Кнопки-подсказки везде, где есть частый ответ (цель, пол, да/нет-вопросы, место тренировок и т.п.) — кнопка не блокирует свой вариант текстом.
- Бот собран и запущен в Docker (`docker compose up --build`), подключён к общей MySQL на машине через `host.docker.internal` — проверено, что и сам контейнер, и запись анкеты работают.
### Changed
- Вопрос «Пол, возраст, рост и вес?» разбит на три отдельных вопроса (пол/рост/вес) — принцип «один вопрос за один шаг»; возраст отдельно не спрашивается, он уже известен по дате рождения.
- `.env`: `DB_HOST` переключён на `host.docker.internal` (бот теперь штатно работает в контейнере, а не на хосте напрямую).
### Note
- Подключение шло к уже существующей на машине базе `health-coach-plan` (не создавалась заново) — в ней были данные предыдущих клиентов, миграции только добавляли таблицы/колонки, ничего не удаляли.

## [0.7.0] — 2026-08-27 04:36 IST
### Added
- `scripts/check-db.js` и npm-скрипт `db:check` — самостоятельная проверка подключения к MySQL текущими настройками из `.env` (без запуска бота).
- В `.env`/`.env.example` выделен явный блок «Telegram-бот» (по аналогии с блоком БД): комментарий, откуда брать `BOT_TOKEN`.
- `tasks.md` — публичный лог запланированных задач и открытых вопросов с временными метками, на которые коммиты ссылаются короткой пометкой вместо полного текста (см. `README.md` → «Коммиты»).
### Fixed
- `src/config.js` больше не бросает исключение при отсутствии `BOT_TOKEN` — раньше это ломало любой скрипт, подключающий `src/db.js` (в т.ч. `db:check`), даже если токен бота ему не нужен. Проверка перенесена в `src/bot.js`, где токен действительно требуется.

## [0.6.0] — 2026-08-26 08:03 IST
### Added
- `Dockerfile` и `docker-compose.yml` — бот в контейнере, опциональный локальный MySQL за Compose-профилем `local-db`.
- `src/db.js` — пул соединений MySQL (`mysql2`).
- Единый `.env` для подключения к MySQL в любом из трёх сценариев: локальный контейнер проекта, MySQL на машине разработчика, MySQL на VPS — без изменений кода, только значения `DB_HOST`/`DB_PORT`/`DB_SSL` и т.п.
- npm-скрипты `docker:up`, `docker:up:local-db`, `docker:down`.
### Note
- Подключение к БД пока не используется кодом бота — задел на будущее. Docker-образ не собирался и не запускался — на машине разработки не был поднят демон Docker.
