## [0.12.0] — 2026-08-29 12:23 IST
### Added
- Новые сущности: `gyms` (залы — привязаны к локации или «типовые»), `equipment_classes` (переиспользуемый справочник — одно и то же оборудование бывает в разных залах) и `gym_equipment` (конкретная сфотографированная единица оборудования в конкретном зале, со ссылкой на класс).
- Бот: `/creategym` (диалог: название → локация/типовой → адрес), `/gyms`, `/gym <id>`, `/addequipment <gym_id>` (диалог загрузки фото одно за другим, подпись к фото = название), `/showequipment <id>` (присылает само фото), `/classes`, `/createclass` (только админы), `/classifyequipment <id> <код класса> [название]` (тот, кто загрузил фото, или любой админ).
- Веб-админка: `/gyms`, `/gyms/:id` (фото оборудования зала + инлайн-форма классификации), `/classes` — то же самое, что в боте, но с миниатюрами фото.
- Фото не копируются в собственное хранилище — только `photo_file_id` из Telegram; веб-админка проксирует байты через себя (`GET /gyms/:gymId/equipment/:id/photo`), чтобы не палить токен бота в HTML напрямую через `getFileLink`.
### Note
- «Обработка фото» пока ручная — классификация по классу оборудования человеком (загрузившим или админом), а не автоматическим распознаванием на фото. Автоматизацию (например, через vision-модель) можно добавить позже поверх той же схемы, не меняя её.
- Ссылка на реальное фото оборудования для тренера при составлении программы — пока только через `/showequipment <id>` в боте или прямую ссылку на `/gyms/:id` в веб-админке; сама программа тренировок всё ещё markdown-файл, автоматической вставки фото туда нет.
- Проверено на уровне данных и через `curl` (создание зала/класса/оборудования, классификация, устойчивая обработка недействительного `file_id` в фото-прокси — 502, не падение) — не проверено вживую через реальную загрузку фото в Telegram.

## [0.11.0] — 2026-08-29 12:06 IST
### Added
- Веб-админка теперь показывает группы клиентов и журнал правок ответов — то, что раньше было доступно только через команды бота.
- `/groups` — список групп + форма создания новой.
- `/logs` — журнал правок ответов (кто/что было/что стало/когда), без ограничения по группе — веб-логин равнозначен полному доступу владельца.
- Колонка «Группа» на страницах «Клиенты» и в карточке клиента — переназначить группу клиента можно прямо там (инлайн-форма, вызывает ту же `clients.setClientGroup`, что и `/setclientgroup` в боте).
- Колонка «Область видимости» на странице «Админы» — какую группу клиентов видит каждый админ, с инлайн-формой для смены (кроме строки владельца — у него всегда «все клиенты», сервер это тоже гарантирует, не только скрытием формы).
### Note
- Веб-логин не завязан на роли `admins` из бота (см. решение в 0.9.0) — у веб-панели нет понятия «своя группа», кто зашёл по паролю видит логи/клиентов всех групп.
- Редактирование самого текста ответа клиента (`/editanswer` в боте) в вебе пока не продублировано — только просмотр журнала; можно добавить, если понадобится.

## [0.10.0] — 2026-08-29 11:52 IST
### Added
- `/continue` — продолжить недозаполненную анкету с того же вопроса; работает и вручную, и автоматически: любое сообщение вне активного диалога (например, после перезапуска бота или на следующий день) подхватывает клиента с сохранённого места вместо игнорирования.
- `/extend` — для тех, кто прошёл короткую анкету: дополнительные вопросы до полной версии (разница между стратегиями `long` и `short`, `getStrategyDelta` в `src/survey.js`), сохраняются отдельным раундом (`round = 2`), после чего `clients.survey_strategy` становится `long`.
- `/editanswer <client_id>` — админ может изменить любой сохранённый ответ клиента (в рамках своей группы); каждая правка пишется в новую таблицу `answer_edit_log` (кто/что было/что стало/когда).
- `/logs` — журнал правок: владельцу видны все, админу с ограниченной группой — правки по своим клиентам плюс собственные правки в любом месте.
- Группы клиентов (`client_groups`): владелец создаёт (`/creategroup`), назначает клиента (`/setclientgroup`, доступно любому админу) и область видимости админа (`/setadmingroup <telegram_id> <код|all>`, только владелец). Админ с группой видит в `/clients`/`/editanswer`/`/logs` только своих; без группы (или владелец) — всех.
- Кнопка меню в боте пополнилась новыми командами по ролям (`src/menu.js`) — `/continue`/`/extend` всем, `/editanswer`/`/logs`/`/groups`/`/setclientgroup` админам, `/creategroup`/`/setadmingroup` владельцу.
### Changed
- `/start` для уже существующего клиента больше не начинает анкету заново — сразу продолжает с сохранённого места (имя/город/дата рождения не переспрашиваются).
- Запросы к клиентам (`upsertClient`, `saveAnswer`, `markCompleted`) перенесены из `src/bot.js` в `src/clients.js` — переиспользуются и сценарием анкеты, и сценой редактирования ответа админом.
### Note
- Веб-админка (`src/admin/server.js`) пока не отражает группы клиентов и журнал правок — доступно только через команды бота. Расширить веб-часть — отдельная задача, см. `docs/todo.md`.
- Разница анкет `/extend` жёстко привязана к кодам стратегий `short`/`long` — при появлении третьей стратегии этот механизм нужно будет обобщить.

## [0.9.0] — 2026-08-29 11:16 IST
### Added
- Веб-админка (`src/admin/server.js`, `npm run admin`, сервис `admin` в Docker Compose, порт `ADMIN_PORT`): список клиентов и их ответов на анкету, CRUD вопросов (`/questions`), управление составом и порядком вопросов в каждой стратегии (`/strategies/:code` — добавить/убрать/переставить местами) — редактирование анкеты без прямых SQL-запросов. Закрыта HTTP Basic Auth (`ADMIN_WEB_USER`/`ADMIN_WEB_PASSWORD`).
- Роли в самом боте — второй вход для администраторов: таблица `admins` (`owner`/`admin`), команды `/stats`, `/clients`, `/admins`, `/addadmin`, `/removeadmin`, `/whoami` (последняя доступна всем — узнать свой Telegram ID).
- Владелец назначается через `OWNER_TELEGRAM_ID` в `.env` (закрепляется при старте бота, если ещё не назначен) — только он может удалять админов; добавлять новых админов может и он, и уже назначенные админы.
- `src/clients.js` и расширенный `src/survey.js` — общие запросы к клиентам/анкетам/конфигурации анкеты, используются и ботом, и веб-админкой.
### Note
- Веб-админка пока не проверялась с реальным браузером, только curl'ом (создание/чтение через формы работает) — визуально не смотрели.
- `admin`-сервис в `docker-compose.yml` публикует порт на `0.0.0.0`, не только на localhost — приемлемо для dev-машины за NAT, но не для публичного хостинга без дополнительной защиты (HTTPS/reverse proxy) — см. `docs/todo.md`.

## [0.8.0] — 2026-08-29 10:49 IST
### Added
- Сценарий онбординга в боте: `/start` спрашивает имя, город, дату рождения, нужна ли программа — и по одному проводит через анкету, сохраняя каждый ответ сразу в MySQL (`clients`, `questionnaire_answers`).
- Анкета вынесена из кода в БД: таблицы `survey_strategies` / `survey_questions` / `survey_strategy_questions` (`migrations/`, `npm run migrate`) — состав, порядок и текст вопросов теперь редактируются в базе, без деплоя.
- Две стратегии анкеты — короткая (9 вопросов) и полная (17), выбор — кнопкой после вопроса «нужна ли программа».
- Кнопки-подсказки везде, где есть частый ответ (цель, пол, да/нет-вопросы, место тренировок и т.п.) — кнопка не блокирует свой вариант текстом.
- Бот собран и запущен в Docker (`docker compose up --build`), подключён к общей MySQL на машине через `host.docker.internal` — проверено, что и сам контейнер, и запись анкеты работают.
### Changed
- Вопрос «Пол, возраст, рост и вес?» разбит на три отдельных вопроса (пол/рост/вес) — принцип «один вопрос за один шаг»; возраст отдельно не спрашивается, он уже известен по дате рождения.
- `.env`: `DB_HOST` переключён на `host.docker.internal` (бот теперь штатно работает в контейнере, а не на хосте напрямую).
### Note
- Подключение шло к уже существующей на машине базе `health-coach-plan` (не создавалась заново) — в ней были данные предыдущих клиентов, миграции только добавляли таблицы/колонки, ничего не удаляли.
