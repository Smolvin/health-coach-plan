# Лог решений (проектный уровень)

Формат записи: `[дата время] — решение — обоснование — версия package.json`. Время — по местному времени клиента (IST, Ирландия), см. `templates/`.

Этот файл — **публичный**, репозиторий открытый: сюда попадают только решения об архитектуре и процессе проекта. Решения, касающиеся конкретного клиента (его цели, программа, план питания), фиксируются в `clients/<slug-клиента>/decisions-log.md` — эта папка в `.gitignore` и наружу не публикуется.

## 2026-08-27 04:36 IST — версия 0.7.0

- **Решение:** добавлен `scripts/check-db.js` и npm-скрипт `db:check` для самостоятельной проверки подключения к MySQL текущими настройками `.env`, без запуска самого бота.
- **Решение:** `BOT_TOKEN` больше не проверяется в `src/config.js` при загрузке модуля — проверка перенесена в `src/bot.js`. - **Решение:** в `.env`/`.env.example` для настроек бота выделен отдельный подписанный блок «Telegram-бот» (аналогично уже существующему блоку БД) с комментарием, где взять `BOT_TOKEN`. Переменную `NODE_ENV` сначала добавили про запас, но убрали в том же коммите — решили не держать в `.env` то, что пока нигде не используется в коде, добавим её, когда появится конкретная задача (логирование, polling/webhook).
- **Обоснование:** явный запрос — продолжить разработку: дополнить `.env` настройками бота и добавить отдельный скрипт проверки подключения к БД, вынесенный в `package.json`. Скрипт проверен вживую — подключился к реальной MySQL на 127.0.0.1:3306 и корректно сообщил об отсутствующей базе `health` (сама база ещё не создана; локально в `.env` `DB_NAME` затем вручную сменили на `health-coach-plan` — оставлено личным override, шаблон `.env.example`/`docker-compose.yml` по решению не синхронизировали).
- **Решение:** зафиксирована конвенция коммитов (`README.md` → «Коммиты»): текст коммита — только «что сделано» (как и раньше), а «что запланировано» и «над чем подумать» в сам коммит не идут — фиксируются с временной меткой в новом `tasks.md`, из коммита на них короткая пометка (`; задачи — tasks.md`).
- **Обоснование:** явный запрос — коммит должен явно разделять сделанное/запланированное/вопросы на подумать, но при этом укладываться в лимит длины сообщения.
