# Health Coach Plan

Проект персонального тренера и диетолога: анкетирование клиентов, составление программ тренировок и планов питания. Клиентов может быть несколько — у каждого своя папка. Проект живой — дорабатывается по мере появления новых данных о клиентах и корректировок прогресса.

## Структура проекта

```
health/
├── package.json                  # версия проекта (semver, см. "Версионирование" ниже)
├── CHANGELOG.md                  # публичная история версий (Keep a Changelog)
├── .gitignore                    # clients/ в git не попадает — см. "Приватность данных клиентов"
├── docs/                          # публично, без персональных данных
│   ├── decisions-log.md          # лог решений уровня проекта (архитектура, процесс)
│   └── todo.md                    # задачи уровня проекта
├── templates/
│   └── questions-template.md     # шаблон 15 вопросов для нового клиента
└── clients/                       # НЕ версионируется в git (см. .gitignore)
    ├── index.md                   # реестр всех клиентов
    └── <slug-клиента>/            # например, anna-berlin (имя-город латиницей)
        ├── profile.md              # карточка клиента: имя, город, цели, параметры, ограничения
        ├── questions-log.md        # заполненная анкета конкретного клиента
        ├── training-plan.md        # программа тренировок клиента
        ├── nutrition-plan.md       # план питания клиента
        ├── decisions-log.md        # решения по этому клиенту (приватно)
        └── todo.md                  # задачи по этому клиенту (приватно)
```

## Приватность данных клиентов

Репозиторий публичный. Папка `clients/` целиком в `.gitignore` — персональные данные (имена, города, здоровье, антропометрия) не должны попадать в git-историю. Локально папка остаётся и используется как обычно, просто не коммитится. Всё, что касается конкретного клиента (решения, задачи), пишется в его приватные `decisions-log.md`/`todo.md` внутри `clients/<slug-клиента>/` — не в общий `docs/`.

## Временные метки

В любом файле с историей (логи решений, todo, таблицы «История версий» в программах/планах) записи датируются датой **и** временем (например, `2026-08-26 06:46 IST`), а не только датой — так проще сверять порядок событий и версии.

## Версионирование

Версия в `package.json` растёт по semver и отражает состояние всего проекта:
- **patch** (0.1.x) — уточнения, правки текущей программы/плана без смены подхода;
- **minor** (0.x.0) — новый этап (новый клиент, новый план тренировок/питания, структурное улучшение проекта);
- **major** (x.0.0) — полный пересмотр подхода (смена методологии проекта в целом).

Каждое изменение версии сопровождается записью в `CHANGELOG.md` и, если это решение архитектуры/процесса, в `docs/decisions-log.md`. Прогресс конкретного клиента (новые версии его программы/плана, решения, задачи) отслеживается в его приватных файлах внутри `clients/<slug-клиента>/`.

## Порядок работы с новым клиентом

1. Узнать **имя** и **город**, создать `clients/<slug-клиента>/`.
2. Провести опрос по `templates/questions-template.md`, сохранить ответы в `clients/<slug-клиента>/questions-log.md`.
3. Заполнить `clients/<slug-клиента>/profile.md`.
4. Зафиксировать решения и задачи по клиенту в `clients/<slug-клиента>/decisions-log.md` и `todo.md` (приватно, не в `docs/`).
5. Составить `clients/<slug-клиента>/training-plan.md` и `nutrition-plan.md`.
6. Добавить клиента в `clients/index.md`.
7. Решения и задачи уровня всего проекта (архитектура, процесс) — в `docs/decisions-log.md` и `docs/todo.md`; значимые версии — в `CHANGELOG.md`.

## Будущее развитие
- Перенос данных клиентов (карточки, анкеты, программы, планы питания) из markdown-файлов в базу данных — конкретная СУБД пока не выбрана, см. `docs/todo.md`.
